# SDK installation, starter and example content

P107 implements the code-first successor at
[addons/game_presentation](../addons/game_presentation/README.md). Copy that entire
directory into any Godot project's `addons/` directory. It includes behavior,
shaders/includes, neutral motion catalogs, API inventory, source UIDs and license.
It has no dependency on the development workspace, game media or Python. The
local canary version records the initial package contract; it is not a release.

## New game

The [starter](../../../templates/vn/README.md) has one editable `main.gd` composition,
its own complete UI, original procedural placeholder art and a small choice/contact
story. Assembly copies this host and the unchanged addon into a new directory,
records file hashes and refuses to overwrite an existing destination. It makes no
provider calls. The `.gdignore` in starter source prevents duplicate editor imports
inside the development workspace and is omitted from the assembled project.

From the repository root, choose a new output directory:

```sh
python3 godot/packages/game_presentation/tools/assemble_starter.py --output /private/tmp/my-presentation-game
Godot --headless --editor --path /private/tmp/my-presentation-game --quit
Godot --path /private/tmp/my-presentation-game
```

The starter's export preset explicitly includes SDK JSON and runtime dependencies.
It can export a PCK and run it with a compatible installed engine; making a standalone
native executable also requires the corresponding Godot export template. Exporting
is local packaging, not publishing. See the starter README for check/export commands.

## Existing examples with external content

Afterlight, Command Link and Presentation Lab retain their existing code and
story-owned catalogs. `--content-root` selects a normalized absolute directory
of prepared raw files. Both games' roots and Lab fixtures receive that same
option; detouring preserves it along with per-game state and language.

The example layout deliberately mirrors current binding paths. It is a host
layout, not a required SDK content schema:

```text
content_root/
    assets/                               Command Link art, layout, Manpu, video
    games/bishoujo_afterlight/assets/      portraits and backgrounds
    games/bishoujo_afterlight/text/        English and Korean display text
    games/bishoujo_afterlight/voice/       policy, casts, speech overrides, manifest
    voice/clips/{en,ko}/       bound recordings and provenance
```

A provider-free helper copies the prepared local files, retaining selected
recording provenance and byte hashes. It excludes scripts, import caches and
generation working directories; the asset directories include prepared alternate
fixtures. It refuses existing destinations and escaping/symlink source bindings.
It requires this checkout's already prepared local example assets. Artwork and
recordings are not part of the BSD-licensed SDK and are not published by this tool.

```sh
python3 godot/games/afterlight/tools/prepare_example_content.py --output /private/tmp/my-presentation-content
Godot --path godot/games/afterlight -- --game afterlight --language ko --content-root /private/tmp/my-presentation-content
Godot --path godot/games/command_link -- --game command_link --content-root /private/tmp/my-presentation-content
```

Without that option, the existing project-resource root remains the default.
The selected external backend never silently falls back to checkout media. The
adapter validates image and catalog bindings before scene setup, while deliberate
no-voice, missing/stale recording policy and video fallback remain host choices.
Prepared recordings are only loaded and inspected, never regenerated by playback.

The SDK loader accepts PNG/JPEG/WebP, MP3/WAV/Ogg, JSON and Ogg Theora video.
Image source bytes preserve existing pixels/mipmaps when available. Imported-only
PCK textures reflect their import settings; use raw external content or matching
import options for exact source-pixel parity. Hosts must explicitly export JSON and
runtime-named media. The starter demonstrates the package/export boundary without
redistributing the example assets.

## Source ownership and verification

Keep source `.gd.uid`, `.gdshader.uid` and `.gdshaderinc.uid` beside their owners;
retain them during moves. `.godot/`, build outputs, editor state and imports remain
disposable. There is one live controller implementation, under the addon. Concrete
`presentation/stage.gd`, stage profile, opening, tactical UI and curve graph are
example integration code. Old Markdown component contracts remain as repository
context and link to the moved sources; the package includes its own usage/API docs.

The [verification record](../history/QA.md#sdk-package-and-content-boundary-p107) separates
source closure, controller checks, external content, gameplay lifecycle, native
rendering and exported-pack evidence. Anatomy/VLM annotation, standing framing,
Scenario integration, upstream generation-family replacement, legacy deletion,
and stable-release/publication work remain outside this implementation.
