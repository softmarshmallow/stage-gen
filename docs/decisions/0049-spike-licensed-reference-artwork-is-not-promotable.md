# 0049 — Artwork derived from a spike-licensed reference is not promotable

*Ruled when the climbable band atlas was accepted.*

## Fact

Every accepted climbable band was generated with a band-structure reference the task owner
licensed for spike use only and explicitly excluded from promotion. Its digest is recorded
beside each run.

## Challenge

The bytes validate, the bands look right, and the reference is only a structural conditioning
input rather than something copied into the output.

## Ruling

Bytes derived from the spike reference are not promoted, whatever they look like. A
self-authored band template with a documented rights basis — the shape the tracked terrain
atlas template already carries — must replace it, and the artwork must be regenerated.

## Evidence

The digest is recorded per run precisely so the derivation is not arguable later, and the
repository already ships a template with the rights basis the replacement needs, so the pattern
is established rather than invented for this case.

## Falsifier

A rights basis for the original reference that covers promotion — which would make the
regeneration unnecessary rather than merely expensive.
