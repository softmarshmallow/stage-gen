Getting a rigged character from a written idea usually means a day of hand-offs: someone draws a
reference sheet, a mesh service turns it into geometry, a rig service adds a skeleton, and a person
checks each file in Blender before paying for the next step. Stage Gen holds that chain as one graph.
An agent draws the references, Tripo builds and rigs the mesh, a local Blender worker checks every
hand-off, and a reviewer that did not make the work judges each result at the size a player sees it.
Each stage has a budget and a second round planned in advance; if a stage cannot be made good, the
run stops and says why.

## Try it

<Try>
<Agent>

Use Stage Gen to make a rigged 3D character from <Ref input="brief">this brief</Ref>. Follow `docs/character-3d.md`: write the experiment file, plan it offline and show me the plan, then run it live with a $10 limit.

When it finishes, show me the export and what the rig reviewer said about it.

</Agent>

```sh
stage-gen run character-3d \
  --experiment work/wren.json --input-root work --run-root work/runs/wren-plan \
  --blender /Applications/Blender.app/Contents/MacOS/Blender \
  --admission-mode development --prepare-only
```

```sh
STAGE_GEN_RUN_LIVE=1 stage-gen run character-3d \
  --experiment work/wren.json --input-root work --run-root work/runs/wren-01 \
  --blender /Applications/Blender.app/Contents/MacOS/Blender \
  --admission-mode development --live
```

Needs an installed `stage-gen` wheel rather than an editable checkout, Blender, and your OpenRouter and Tripo keys. The [guide](https://github.com/softmarshmallow/stage-gen/blob/main/docs/character-3d.md) shows the experiment file.

## Where it works

<Scope>
  <Works>Adult characters drawn chibi-style, about two and a half heads tall</Works>
  <Works>Short hair that sits close to the head</Works>
  <Works>Hands drawn as closed mittens</Works>
  <Works>Outfits that stay close to the body, such as jumpsuits, jackets and trousers</Works>
  <Works>Games that show the character small on screen, around 120 pixels tall</Works>
  <Limit>Long hair, ponytails and braids: hair is fixed to the head and does not move</Limit>
  <Limit>Animals, and characters carrying weapons, capes, scarves or props</Limit>
  <Limit>Facial expressions, finger movement and cloth that moves on its own</Limit>
  <Limit>Close-up shots: small seams are allowed at the size it is judged</Limit>
  <Tip>The export has a cheer and five test poses. Walk, run and idle come from your own animation library, retargeted onto its skeleton.</Tip>
  <Tip>Skirts where the hands rest often need a second rig. That run takes longer and costs more, up to about $8.60.</Tip>
  <Tip>Needs Blender installed, on macOS or Linux, and your own model and 3D service keys.</Tip>
</Scope>

## What goes wrong by hand

<Guards>
  <Guard node="references_review_01" how="A second model that did not draw the views checks that front and back agree before any mesh is paid for.">A back view that is really a front goes to the mesh service, and the mesh is paid for twice.</Guard>
  <Guard node="part_review_character_01" how="Every view is rendered in the matte material the export will use before anyone judges it.">The mesh looks right in the service's glossy preview and wrong in the game.</Guard>
  <Guard node="rig_review_01" how="The reviewer sees every pose from five sides. A refused rig sends the mesh back for one more attempt.">A skirt or strap is tied to the hands, so it lifts whenever the arms move.</Guard>
  <Guard node="rig_01" how="The rigged mesh is compared with the approved one, triangle for triangle, and any change is refused.">The rig service quietly alters the mesh, and the shading turns bumpy.</Guard>
  <Guard node="runtime_admit" how="Blender is checked before anything is paid for.">A missing Blender feature turns up after the money is spent.</Guard>
</Guards>
